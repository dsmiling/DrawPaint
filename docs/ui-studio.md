# UI 素材模式

## 拆图上下文开销

CLI 的 claim/request 保留完整生成提示词、质量配置、参考路径、批准方案、修补请求和复用候选，省略重复的历史候选和 Mask 草稿。complete 系列命令仅输出状态、图层文件及尺寸、质量警告与后续任务编号，避免把已读的任务说明再次送入上下文。追加 `--full` 可读取完整响应，`--help` 显示全部命令。服务端任务记录、生成质量、图像分辨率和审核校验不受影响；这些优化节省的是文本上下文，不承诺固定比例的 token 或账单下降。

## 图层回填完整性

回填前先完成当前画布交互，并将新图片明确放到当前页，避免分组取消交互时撤回新图片，或误挂到当前聚焦组。创建、分组和替换结束后，按任务版本逐层校验图片记录及其资源 URL；事务结束后再检查一次。缺图、缺资源或资源不匹配都会回滚，保留原画布，不记录导入成功。重做替换采用同样校验。历史空组会自动补回；手动定位不完整结果时会重新回填，已整体删除的结果不会仅因历史记录而自动复活。

## 当前默认：完整结构的高清拆分

### 透明渐变与底色去污染

普通图集切图（外部去底、全部同色去底）、逐层 AI 拆图和 Mask 参考/合图拆图共用边缘处理：沿与背景相连的污染渐变去除品红或绿色残色，同时输出分数 Alpha，不把光晕压成硬边。生成指令要求保留真实 RGBA、选择与素材不冲突的底色，并在深浅背景检查导出边缘。已有真实透明素材和原像素保留路径不强制重新抠底；关闭去背景时保留原图。历史已污染的 PNG 不会自动修复，需从带底色原图重新处理，或重新生成。

单张纯色底图片无法唯一求解原始透明度；当前算法适合与底色可区分的光效，不能保证还原与底色同色的半透明装饰。此类素材优先输出真正透明的 PNG。

拆图完成后按最终 PNG 的实际宽高比，在计划范围内居中适配布局（坐标取整到像素）。普通、高清、图集合图和复用结果统一保留原生 PNG；不再强制拉伸到计划宽高。清单以 `plannedRect` 保存原计划范围，`x/y/w/h` 保存适配后的布局；画布、回拼预览和导出使用该布局。原像素保留模式维持原坐标。重做时保留未选图层的图片及布局，并同步更新重做图层在画布中的尺寸。

组件“拆分”默认逐层高清生成，保持主要轮廓、比例、配色和风格，允许修复模糊、马赛克及少量局部细节变化。相连边框、端头、角饰和镶嵌装饰规划为一个完整 `border` 图层，不沿连接点拆成碎片；文字、独立图标、底板仍分离。用户明确要求时才单拆连接结构。旧方案不会自动改写，需要从原组件重新分析才能采用合并后的范围。

Mask 用于识别元素归属，高清任务不允许切换成精确裁切或提交 `sourcePixels`。新生成与复用素材均保留原生分辨率；建议有效内容长边至少 1024 像素，服务端拒绝低于 768 像素的内容，透明留白不计入门槛。低分辨率素材从高清复用候选中排除，实际复用再次检查 PNG，防止低清图混入高清结果。此检查不是视觉清晰度评分，不能识别所有插值放大或生成缺陷，Agent 仍须对照原图检查轮廓、接缝、镂空和深浅底上的边缘。

当前组件入口会自动分析、处理和回填。下方逐步校正、逐层确认流程适用于手动任务和旧任务。

## Mask 边界参考与 AI 完整图层生成

复杂组件默认使用 `maskPurpose: reference`。OCR 提供文字线索，LLM 规划元素、坐标和遮挡关系，SAM 生成可编辑的边界参考。原图、编号叠加图、每层原始局部、Mask 与用户说明一起交给生图 Agent；先查找并复用匹配的已有图层，只为缺失或不匹配的部分生成完整独立 PNG。

Mask 仅表达元素归属和大致边界，不决定最终透明度，不限制生成像素，也不要求用户逐像素描边。AI 可以修正毛边、补全遮挡和细线。生成结果自身的轮廓与 alpha 用于输出；若使用声明的均匀纯色背景，则根据生成图去底色，绝不使用旧 Mask 裁切。

### 本地视觉环境

```powershell
./scripts/setup-ui-vision.ps1 -Python '你的 Python 3.12/python.exe'
# 无 CUDA 可加 -Cpu；重用 PyTorch 可加 -SkipTorch。
node scripts/ui-studio.mjs vision
```

环境及 SAM ViT-B 权重位于 `.cache/ui-vision/`。OCR / SAM 在本机运行，SAM 每个任务只编码一次；AI 分析和生成由连接的 Agent 执行。可用 `DRAWPAINT_VISION_PYTHON` 和 `DRAWPAINT_SAM_CHECKPOINT` 指定已有环境。

### 操作流程

1. 从效果图分析拆解方案，或在组件上选择“AI 继续细分 → Mask 参考 · 分析拆解方案”。
2. 选择“Mask 边界参考 · AI 完整生成”，确认组件范围、类型、精确文字、父层关系和拆解要求，点击“生成边界参考”。
3. 打开“调整边界参考”。默认显示原图与标注叠加；画笔可标记目标、排除干扰。补充“本层生成要求”后保存。Mask 有缺口或为空仍可结合原图和说明生成。
4. 点击“使用参考生成完整图层”。Agent 将原图与标注作为实际生图参考，输出每个元素的完整高清图层。
5. 回填后停在“待验收图层效果”。逐层对照原图局部和生成结果，检查内容/文字、比例位置、细线镂空、深浅底上的透明边缘、底板是否残留前景。支持原始分辨率查看和 PNG 下载。
6. 不满意时“调整参考 / 重新生成”，修改标注或文字要求。满意后“确认图层并回填画布”。关闭或刷新不会重复生成；未确认结果不进入正式预设导出。

### 分辨率与导出

`x/y/w/h` 是源图坐标中的布局范围；`imageWidth/imageHeight` 是 PNG 的真实分辨率。PNG 图层包和 Unity 包保留生成素材分辨率，画布和 Unity 布局继续使用原坐标/尺寸。PSD 可按 1×、2×、4× 布局尺寸导出，清晰度取决于生成素材。继续细分高清图层时保留高清参考原件，同时建立布局尺寸的工作图供坐标分析。

默认自动去除透明外边距；如果生成内容需要保留相对布局的透明余量，Agent 先查看图片，再提供 `generatedRect:{x,y,w,h}`，表示生成图片内对应完整布局框的范围。裁取该范围后仍保留其原始分辨率和透明余量。禁止越界范围，禁止猜测映射；宽高比偏差超过 8% 时拒绝拉伸，需重新生成或校正框选。

图层 ZIP 含高清 PNG、布局清单、原图、编号标注、各层参考 Mask 和差异图。差异百分比只说明变化，不能代替视觉验收，也不以旧 Mask 的像素一致率评判生成质量。文字默认是图片，字体不明时不猜测；可编辑文字仍需指定可用字体。

### Agent 回填协议

```powershell
node scripts/ui-studio.mjs claim <jobId>
# 查看 referencePaths，以及每个 repairRequests 的 imagePath / guidePath / maskPath。
# 先查 reusableComponents；匹配层返回 reuse，缺失层才将原图与边界参考交给 imagegen。
# {"repairs":[{"regionId":"panel","imagePath":"C:/absolute/panel.png","background":"#ff00ff"}]}
# 真正透明的 PNG 不填 background；完整矩形背景才可用 allowOpaque:true。
# 需要保留透明余量时按实际生成图填写 generatedRect。
node scripts/ui-studio.mjs complete-repairs <jobId> 'C:/absolute/layers.json'
# 到 review_repairs 即结束 Agent 回填，用户在画布验收。
```

生成前先检查 `reusableComponents`，对照已有图片的图案、颜色、精确文字、状态及清晰度。匹配图层返回 `{regionId,reuse:{jobId,revision,sliceId}}`，不再调用生图；仅对缺失或不匹配的层提交新 PNG。支持全部复用或新旧混合；复用保留原生像素和透明留白，校验来源版本、类型、文字及比例，界面显示“已复用”和复用数量。候选清单按类型、文字和比例预筛选，最终视觉匹配由 Agent 判断。

接口名 `complete-repairs` 为兼容旧任务继续保留。`reference` 任务要求返回所有图层；每层只接收一次，任何图层失败则不发布。参考修改有版本校验，返回修改会清除旧预览。新增协议集中在 `server/ui-studio/reference-layers.mjs`。

历史任务的 `cutout` 模式仍保留原像素和局部修补机制，可在“Mask 用途”中切换为参考模式。新任务默认参考模式，原有透明/纯色图集直接切片不受影响。

UI 素材是 DrawPaint 的独立扩展模式，入口是顶部「UI 素材」，也可直接打开 `http://127.0.0.1:43217/?mode=ui`。

模式拥有自己的 tldraw 画布、任务、参考图、原图、切片及生图配置。普通「AI 图片」、图片框、标注改图和普通 pending 请求均保持原有协议。

## 效果图优先工作流（第一版）

右侧默认选择「效果图拆解」，也可切回「素材图集」使用原有流程。

1. 生成完整界面，或切到「提取 UI」导入效果图。可以点击「填入丝之歌主菜单示例」作为起点。效果图使用独立的完整构图提示词，强制保留背景、关闭自动切图；原始尺寸和像素保留。
2. 在效果图工作流卡片点击「分析拆解方案」。Agent 只查看图片并返回组件范围、类型、文字和层序，不调用生图。
3. 打开「校正方案并拆解」。点击组件列表或标框选中组件，拖动标框移动、拖右下角调整大小，或输入像素坐标。可以修改名称、类型、文字、层序、拆解要求，添加或移除组件。用途分组作为 AI 的拆解参考，画布层级仍可在图层树编辑。关闭窗口保留本机草稿。
4. 确认方案后才生成独立素材。Agent 必须保留每项 regionId、名称、类型、文字、坐标和层序，清理背景中的前景元素并补全遮挡。服务器校验方案、透明度和宽高比后一次性发布。结果自动按源像素布局在原图旁边拼成可编辑组。
5. 「原图 / 结果对照」通过滑动分界线比较原图和生成时的拼回结果。选中子组件可继续 AI 细分；失败后使用「调整后重试」，已有原图和结果不覆盖。
6. 选中拼回结果组，展开「导出预设 · PSD / Unity」，默认「当前画布布局」，导出前会显示该次导出预览和下载链接。

没有 Agent 连接时可以保存效果图、分析或拆解任务，连接后再从任务记录启动。重复提交、取消后回填和失效来源方案会被拒绝。效果图和拆解方案都使用现有独立任务连接器；分析方案走 `complete-plan` CLI 回填。

当前画布导出包含所选节点及后代的移动、缩放、复制、层级、翻转、直角旋转、透明度和显隐，范围取组件整体包围盒。隐藏图层保留在 PSD 中，Unity 导入后不激活。任意角度旋转、裁剪、跨页子节点以及交错叠放的图层组会提示先整理后导出，避免静默丢失外观。翻转或旋转的文字保留栅格外观。原图/最新分层导出继续使用源像素布局；最新分层现在也替换整张效果图的根级拆解结果。

验证：新增自动化测试覆盖完整像素保留、生成提示词、分析与编辑方案、失败/取消/重复回填、版本失效、根级分层导出、画布尺寸/位置/隐藏副本/透明度和 PSD 回读。浏览器使用隔离固定素材验证方案修改、失败后重试、自动拼回、移动、复制、隐藏、PSD/Unity 导出及对照视图；没有用固定素材测试冒充真实 AI 生图质量验证。可用 `node scripts/ui-workflow-preview.mjs` 启动隔离测试页面（43227），测试数据在 tmp 中，不写入用户画布。第一版未执行完整的真实 AI 效果图→多层生成测试，也未在目标 Unity 项目内验证导入编译。

## 生图到切图

程序生成的 Agent 任务指令、生图提示词、拆分规则和默认任务描述统一使用英文；界面按钮、状态提示和组件显示名称保持中文。示例提示词使用英文描述，并保留需要出现在图片中的中文原文。用户输入、标注、文件路径和图片中的精确文字不自动翻译或改写。Agent 被要求使用英文编写后续模型提示词，面向用户的结果摘要使用中文。普通画布的生图与标注改图提示词也遵循此规则。更新提示词后，已运行的连接器需要重启才会使用新的任务指令；已派发的对话不追溯修改。

1. 在「生成 UI」描述素材清单和风格，可添加最多 4 张参考图。
2. 选择尺寸与质量。默认启用「移除背景」和「自动拆分」。
3. Agent 已连接时，点击「生成 UI 素材」会新建独立对话，由新对话使用内置生图工具。执行对话保留供检查，不自动归档。没有 API 配置弹窗，也不需要复制指令。未连接时显示「Agent 待连接」。
4. 生图提示词会要求组件完整、分开排列、保留间距和使用纯色背景。生成完成后，服务器自动去背景、检测组件并导出独立 PNG。
5. 画布只自动放入处理结果，每个切片可独立移动、缩放。原图保存在任务记录，可通过「查看原图」打开，避免原图和整图切片重复显示。点击「校正切片」可修改范围、名称，框选新增，合并、拆分或移除切片。
6. 「下载 ZIP」导出 `sprites/*.png` 和 `manifest.json`。清单使用左上角原点，包含原图像素坐标、尺寸和文件名。

### 独立 Agent 对话与链路检查

界面统一使用 Agent，复用当前会话的内置生图能力。旧版等待 Agent 的任务显示为「待启动」，连接后点击「开始生成」可提交原任务，不会另建任务。Agent 忙碌时由会话处理队列；每个任务先领取，再生图回传，重复提交或领取会被拒绝。

`scripts/ui-agent-bridge.mjs` 通过已安装的 app-tools MCP 插件连接桌面。启动对话只提供连接环境；每次生图、AI 细分或分类均使用 `create_thread` 新建 projectless 对话和独立输出目录，不向启动对话或上一次生图对话追加消息，不 fork 历史，不指定模型或修改权限。新对话通过绝对路径 CLI 读取本次任务及明确提供的参考图、已有组件；素材复用不需要继承对话历史。

连接器只监听回环地址，使用随机连接凭证，拒绝浏览器 Origin，只接受任务 ID；提示词从本项目任务读取，不能传入任意工具名称或目标会话。连接凭证保存在被 Git 排除的 `canvas/ui-studio/agent-connection.local.json`，不会返回浏览器。任务与新对话的对应关系保存在 `agent-threads.local.json`，创建前先落盘，同一任务重复提交、响应不明确或进程重启均不会自动再建对话。

连接器每 15 秒检查自己创建的独立对话并记录执行结果。成功、失败、取消均保留对话，不调用自动归档；重启后同样不会归档。对话已结束而素材任务仍未完成时记录提示，既不自动重建对话，也不重复生图。

每张素材任务卡的“检查回填链路”可查看方案及后续图片任务、错误、素材文件是否存在、当前编辑器和已保存画布的实际图层数量。导入历史标记、空组或重复图层不算完整回填。`ready` 表示服务器素材已准备好，不保证浏览器已经回填或保存，也不表示视觉验收通过。检查面板可打开执行对话；仅当用户点击时恢复历史已归档对话。Agent 可运行 `node scripts/ui-studio.mjs diagnose <jobId>` 获取同一检查结果，最终回复须分别报告处理结果与保存回填状态。

验证覆盖独立创建、防重复、完成及失败后保留对话、重启恢复，以及方案成功但生图失败、文件缺失、部分画布图层和错误图片引用的诊断。

从已授权的当前 Codex 任务启动连接器：`node scripts/ui-agent-bridge.mjs`。连接器需与本地画布服务保持运行；退出或重启桌面应用后若显示未连接，可由当前 Agent 重新启动。此前已经授权的同一连接范围无需重复询问授权，执行环境仍会执行其正常的权限检查。

Codex 独立任务通过本地 CLI 领取和回传任务（先运行 `npm run dev`）：

```powershell
npm run ui:job -- list
npm run ui:job -- request <jobId>
npm run ui:job -- claim <jobId>
npm run ui:job -- complete <jobId> "C:\absolute\ui-atlas.png"
npm run ui:job -- fail <jobId> "简短失败原因"
```

UI 模式使用独立任务目录和 CLI，不应读写或清理普通 `pending-request.json`。

### 保留的可选 API 后端

API 后端仅保留兼容性，界面不使用它，也没有 API 设置入口。只有调用后端并显式传入 `provider: "api"` 的集成才走此路径。支持 [Images API](https://developers.openai.com/api/docs/guides/image-generation) 的 `images/generations` 和带参考图的 `images/edits`，响应须包含 `data[0].b64_json`。

兼容后端默认模型字段为 `gpt-image-2`。模型是否可用、支持哪些尺寸、质量和账户权限由服务提供方决定。不会静默切换模型或在失败时自动重试付费生图。这个配置不影响 Agent 的内置生图。

配置也可通过独立环境变量提供：

```powershell
$env:DRAWPAINT_UI_BASE_URL = "https://api.openai.com/v1"
$env:DRAWPAINT_UI_MODEL = "gpt-image-2"
$env:DRAWPAINT_UI_API_KEY = "<在本机设置密钥>"
npm run dev
```

UI 保存的配置优先于环境变量，保存在 `canvas/ui-studio/provider.local.json`（本地明文，已排除 Git）。密钥不返回前端。切换服务地址且未提供新密钥时会清除旧服务的密钥。可用本机 HTTP 兼容接口；远程接口使用 HTTPS。

## 提取已有图集

「提取 UI」支持上传静态 PNG、JPEG、WebP，或使用 UI 画布选中的图片。单张图片不超过 32 MB / 1600 万像素。建议使用原始图集；截图中的工具条、选框、画布网格也会被当成图像内容。

参数说明：

| 参数 | 用途 |
| --- | --- |
| 背景颜色 | 生成默认使用品红色，提取默认从图像边缘估计背景色 |
| 从外部移除 | 删除与图像外边缘连通的背景，保护封闭轮廓内的浅色图案 |
| 移除全部同色区域 | 同时清理镂空内部；适合前景不含背景色的品红/绿底图集 |
| 颜色容差 | 提高可去除更多接近背景色的像素，过大可能损失前景 |
| 边缘过渡 | 为接近背景色的边缘像素保留过渡透明度 |
| 最小面积 | 过滤小于指定面积的碎片；小圆点也需要导出时应降低 |
| 切片留边 | 给切片边缘增加像素留白 |

算法保留已有透明图集的 alpha，使用八连通区域检测，合并框内的部分小型孤立细节，并让自动切片只包含归属自己的像素，避免大矩形重复包含其他组件。饱和纯色背景额外处理边缘色溢出。

「按组件切图」和「移除背景」分别控制组件范围识别与输出透明度。保留不透明背景时仍使用临时去背景掩膜寻找组件，但导出矩形切片保留原始像素和背景；不会把整张纯色图集直接判成一个组件。

本地自动切图针对**分开排列的素材图集**，只识别像素连通区域，不推断组件语义。需要拆开重叠的文字、图标、底图时，使用下方 AI 细分流程。白色前景与白色背景仍无法仅凭颜色可靠区分。

## 父子图层与 AI 递进细分

1. 切图后，左侧「图层」显示任务、组件及后续细分结果的父子结构。点击节点可选中并定位画布素材；直接选中画布图层也会高亮对应节点。支持折叠、展开和方向键导航。
2. 在左侧节点上右键，或在画布选中的组件/图层组上右键，选择「AI 继续细分」（左侧按钮仍可使用）。填写要求，例如「底图去掉字和图标并补全；边框保持镂空；文字单独保留」。左侧右键会先选中该节点，支持 Shift+F10 打开菜单、Esc 关闭。没有 Agent 连接时可以保存待启动任务，连接后在任务记录中点「开始细分」。
3. Agent 查看选中节点的原始素材，分析语义，再为底图、ICON、文字、边框、装饰或子组件分别生成 PNG。服务器根据显式坐标和 zIndex 合成预览，不再用连通区域算法猜测图层归属。
4. 新图层在原组件旁边组成一个可展开的画布组，内部按父组件坐标叠放。左侧挂在来源节点下面；原始组件保留用于对照。选中任意子图层，可继续细分，最多 12 级。同一节点同时只允许一个未结束的细分任务。
5. 可显示/隐藏所选层、下载单层 PNG，或下载当前细分任务的图层包。新增的「导出预设」支持所选预设/组件及其最新成功的递归子图层，生成分组 PSD 或 Unity uGUI 导入包。

### 预设操作、语义类型与字体

左侧大节点是预设，下面是组件及细分版本。选中预设后，其当前画布图片组成一个可拖动的组；双击组或点击树中子节点可继续选择内部图层。属性区实时预览所选图片的移动和显隐，提供放大查看及每次 10 像素的移动按钮。移动同时用于“当前画布布局”导出；原图/最新分层方式使用源像素布局。

属性区可命名预设、修改组件名称和类型，支持组件、按钮、文字、图标、贴图、背景、边框、装饰。分类是独立元数据，不重切图片，也不改变切片版本或父子关系。「校正切片」也可设置类型；重新切片保留传入的语义字段。

文字可保留 PNG 外观，同时记录文字内容、字体资源名、字号、颜色、对齐方式和 Unity 显示方式。未知字体留空。开启可编辑文字后，Unity 导入器寻找同名字体的 TMP_FontAsset；缺少字体或 TMP 时会保留图片并提示原因，避免生成看不见的文字。

「AI 识别类型」仅分析现有图集及切片，不调用生图。结果按版本和属性版本校验，期间人工修改过的属性不会被旧识别结果覆盖。生成提示词预先要求语义规划，Agent 生图回填后继续查看实际切片并填写分类。无法识别的内容保留“组件”；纯像素切图本身不会凭形状猜测语义。

### PSD 与 Unity 导出

选择节点，在「导出预设 · PSD / Unity」中选择原图或最新成功分层，生成后下载文件和组件清单。最新分层会替代该组件的平面图，失败结果与旧来源版本不参与合成。PSD 使用真实 RGBA 像素和分组；文字仍是栅格层，类型、字体和可编辑内容保存在对应 preset.json。PSD 写入采用 [ag-psd](https://github.com/Agamnentzar/ag-psd)，不声称恢复原始设计字体。

Unity ZIP 解压到项目根目录并合并 Assets。选中包内 preset.json，执行 **Assets → DrawPaint → Build UI Prefab**，通过 [PrefabUtility.SaveAsPrefabAsset](https://docs.unity.cn/cn/tuanjiemanual/ScriptReference/PrefabUtility.SaveAsPrefabAsset.html) 创建独立预设。导入器按类型创建 Image、Button 和可编辑 TMP 文字，保留层级、尺寸和文字元数据。生成的预设放入项目现有 Canvas 使用；交互还需要场景中的 GraphicRaycaster / EventSystem，不自动绑定业务逻辑。多个包共享同一路径的导入器，预设素材放在独立目录，已有 .prefab 不覆盖。

验证覆盖：PSD 写出后重新读取，核对分组、图层像素/透明度和坐标；Unity ZIP 核对素材、类型/字体字段与导入脚本。尚未指定目标 Unity 项目时，不会直接写入现有项目，也不视作完成该项目内的编译和运行验证。

这是对扁平图片的 **AI 重建分层**，无法无损恢复原 PSD。遮挡部分由 AI 补全，文字是透明图片图层，非可编辑字体对象；应核对内容和视觉细节。Agent 无法有意义地进一步拆分时应报告失败原因，不能用整图复制或矩形裁剪冒充语义分层。真实输出质量取决于模型，自动化测试使用固定图像验证导入与层级流程，不代表 AI 图像质量保证。

节点关联包含来源任务、来源版本和切片 ID。父任务重新切图后，旧细分结果显示为「历史来源」，不会因切片 ID 被复用而挂到错误的新组件上。结果及画布选择/位置持久化，旧文件不覆盖。

Agent 回填示例：

```json
{
  "layers": [
    { "name": "按钮底图", "layerType": "background", "imagePath": "C:/absolute/base.png", "x": 0, "y": 0, "w": 240, "h": 80, "zIndex": 0 },
    { "name": "开始文字", "layerType": "text", "text": "开始", "imagePath": "C:/absolute/text.png", "x": 80, "y": 25, "w": 80, "h": 30, "zIndex": 1 }
  ]

```

```powershell
node scripts/ui-studio.mjs claim <jobId>
node scripts/ui-studio.mjs complete-layers <jobId> "C:/absolute/layers.json"
```

普通 `complete` 会拒绝分层任务，分层结果必须使用 `complete-layers`。清单须包含 2–64 个图层，边界不能超出父组件，总面积不超过 1600 万像素。图片导入时映射到清单指定的 w/h，因此生成图应匹配该宽高比。

取消任务不会自动触发再次生成；远端已接受的请求是否计费由服务决定。服务重启会将中断任务标记为失败，保留已生成原图。可从原图重新切图，无须重新生图。导出版本使用不同目录，旧 PNG/ZIP 不覆盖。

### 已有组件复用

AI 细分领取任务时，`reusableComponents` 会列出当前项目已完成任务中的组件，包括旧任务的素材路径、名称、分类、文字、尺寸和版本引用。Agent 先打开可能匹配的图片，核对图案、颜色、文字及状态，匹配时直接引用，仅为缺少的图层调用生图。不同文字、颜色或状态不能仅凭名称相近复用。

复用图层清单示例（与新生成图层可混用，也可全部复用）：

```json
{
  "name": "确认按钮底板",
  "layerType": "background",
  "x": 10, "y": 20, "w": 200, "h": 60, "zIndex": 0,
  "reuse": { "jobId": "已有任务 UUID", "revision": "已有版本 UUID", "sliceId": "slice-1" }
}
```

该条目无需 `imagePath`、`dataUrl` 或 `background`。服务器校验引用存在、版本一致、分类及文字匹配、宽高比偏差不超过 2%，直接读取原素材，不重新抠图或裁掉留边；新位置和图层属性独立保存。失效引用会报错，不能用父组件整图冒充分层。候选比较由 Agent 完成，视觉相似并不保证自动命中。

自动切图和 AI 分层在保存时按尺寸与 RGBA 像素计算内容摘要，忽略完全透明像素中不可见的 RGB 差异。相同图片在 `canvas/ui-studio/component-images/` 中共用存储，各版本以硬链接保留可独立访问的 PNG；素材 ZIP 和 Unity 包中重复图片只存一份，图层实例及位置仍全部保留。任务卡显示复用图层数和共用存储图片数。旧任务可以直接作为引用来源，不会批量删除或修改旧结果；重新处理后使用新存储方式。

### 分层透明度与恢复

分层生成优先使用均匀品红色（素材含品红时用绿色）背景，并在每层清单中声明 `"background": "#ff00ff"`。服务器校验边缘底色，再移除外部和镂空区域的底色，裁掉透明留白后映射至坐标。真实透明 PNG 可省略 `background`；完整矩形底图可显式声明 `allowOpaque: true`。棋盘格不是透明背景，服务器会拒绝不透明图层、空图层及宽高比明显不匹配的结果。

整批图层全部通过校验后才发布新版本。失败或取消保留原组件及参考图，任务记录提供「定位原组件」「查看原图」「调整后重试」；重试创建独立任务，不覆盖失败记录。画布回填先创建新素材，成功后更新旧版本，异常时恢复回填前的画布。

图层节点和「定位素材」会跨页寻找素材，自动切到所在页并缩放显示。每个标签页独立记住页码和视角，刷新后恢复。画布加载失败时暂停保存；保存使用版本校验，旧窗口不能覆盖新窗口记录。冲突时可下载当前画布备份并加载最新记录。服务器还保留 `snapshot.previous.json`，从有图变为空图时额外保留 `snapshot.before-empty.json`。

### 图层树交互与画布属性

左侧节点支持拖拽：行中间表示放入该节点，上下四分之一区域表示同级前后排序；底部「移出父节点」区域可提升为根节点。禁止把节点放进自身或后代，跨页的图片须先移到同一页。展开 / 折叠仍用小三角；双击名称或 F2 进入改名，Enter 保存，Esc 取消，失焦也保存。失败任务没有可编辑素材，继续保留来源和错误记录。

树的编辑关系与顺序保存在 UI 画布 document.meta.uiHierarchy 中，随画布自动保存并支持撤销；AI 来源关系不变，继续细分仍使用原始切片。选中节点会选中当前页该节点及其子节点的图片，可整体拖动；单个嵌套组件会进入其画布组，避免拖动时误选整个外层组。

图层树右键菜单提供「复制副本」「重命名」「显示/隐藏」「定位到画布」「AI 继续细分」「删除」。树行获得键盘焦点时，Ctrl+D 复制整个节点及子节点，F2 改名，Delete 删除；菜单支持方向键、Home/End 和 Esc。复制后在同一父节点下建立独立副本，图片向右下偏移 24 像素，保留类型、文字属性和显隐状态。副本的独立标识及属性保存在 `document.meta.uiLayerEdits.copies`，图片通过 `meta.uiNodeKey` 关联，修改副本不修改原节点。跨页子节点须先移到同页才能整组复制。

删除同步移除节点及后代的画布图片，并记录文档删除标记，原始任务和素材文件仍保留。复制、删除、层级调整及副本属性编辑使用可撤销的文档记录写入，避免 tldraw `updateDocumentSettings` 默认忽略历史导致图片与树的撤销状态不一致。锁定图片须先解锁；包含运行中任务须先取消任务。撤销、重做同时处理图片与图层树，刷新后保留副本及删除状态。AI 分类/继续细分仍在原始节点执行，副本用于独立排版；PSD/Unity 的“当前画布布局”导出包含副本和层级编辑；另外两种导出方式仍基于原始素材结构。

属性面板同时显示世界 X/Y、局部 X/Y 和宽高（像素），回车或失焦应用，可 Ctrl+Z 撤销。世界坐标以当前画布原点为基准；局部坐标是节点世界坐标减去树中直接父节点的世界坐标，两者均以 X 向右、Y 向下为轴，不是 Unity 三维 Transform 或锚点坐标。根节点的局部坐标等于世界坐标。修改任一坐标会同步另一组；父节点整体移动时，子节点世界坐标跟随、局部坐标不变。

组件原点是其图片左上角，不随后代图片越界改变。预设原点首次由原始切片布局推算，此后独立保存在 `document.meta.uiCoordinateOrigins`（按页面和节点区分）；子图层越界不会推动预设原点。画布拖动和撤销时同步更新整体移动的预设原点，恢复页面后仍保留。更换父节点保留图片世界坐标并重新计算局部坐标；当前页缺少父组件图片时，局部坐标暂不可编辑。

预设尺寸修改同时缩放子图层及其相对位置。任意角度旋转的图片须先恢复为直角才能数值调整宽高。树行显隐按钮和属性「显示」开关同步；隐藏保留图片和尺寸，显示父节点会保留单独隐藏的子图层。

这些层级、尺寸和显隐操作可通过“当前画布布局”导出；选择“原图”或“最新成功的子图层”时仍按生成来源与源像素布局组装。

加载保存的画布后会清空撤销历史，作为本次编辑的初始状态。撤销只作用于加载后的操作，不能撤销到加载前的空白编辑器；刷新验证时同时检查撤销按钮初始禁用。恢复记录仍保留原有版本校验和非空备份。

## 拆分配置

组件属性和右键菜单的入口统一为“拆分”。弹窗提供保留原图外观、Mask 边界参考、保留文字、拆分粒度（独立图层 / 完整组件）与补充要求，仅保留一个“拆分”提交按钮。关闭 Mask 时直接拆分，开启时先分析并审阅边界参考。关闭保留文字会要求移除全部可读文字并补全材质。

选项和补充要求在修改时保存到本机浏览器的 `drawpaint.ui-studio.split-options.v2`，关闭、切换组件及刷新页面后继续使用。首次从 v1 迁移时将输出调整为高清、逐层生成和保留外观，同时保留文字、Mask、粒度及补充说明的选择；之后明确选择原像素或合图仍会记住。旧任务配置不改写。清除浏览器站点数据会清除偏好。任务将配置保存为 `splitOptions`，分析到完整生成持续传递，优先于通用提示词。

默认开启“保留原图外观”，输出方式默认为“高清拆分”。外观保真约束人物、造型、颜色和线宽，不限制输出像素尺寸；有无 Mask 都保留生成或复用 PNG 的原生分辨率，布局坐标另行保存。Mask 只提示边界，不能直接决定高清输出的透明度。

“原像素提取”是单独的可选输出方式，保留原始分辨率，小图放大后不会增加细节。此方式由 AI 修正元素归属，服务器复制原 RGB，仅局部采用补画。两种方式及文字、Mask 等选项均持久保存。旧任务的像素提取协议保持不变，旧浏览器配置迁移到默认高清。

保真回填协议：`sourcePixels:{alphaPath,repairMaskPath?,repairImagePath?}`。全部图片尺寸须与该层的原始布局框一致，alpha 与 repairMask 为不透明灰度图；CLI 转为 `alphaDataUrl/repairMaskDataUrl/repairDataUrl`。修补范围与修补图成对提供，不得混入整层 imagePath 或 reuse。服务端检查尺寸、透明度和范围，语义归属及遮挡补全仍须通过原图/回拼视觉验收。

### 合图生成后切割

高清拆分默认使用 `generationMode:"individual"` 逐层生成，也可选 `sheet` 合图以减少调用。原像素模式不生图集。合图优先每张 2–4 个、最多 8 个，只缺一个时可单张；每个裁切后的有效元素须独立满足高清分辨率要求。提示词要求充分留白、统一抠图底色和无重叠，根据实际图片检查坐标；细节不足时减小批量或逐层生成，不能通过简单放大冒充高清。实际 token/费用取决于输出尺寸和重试。

CLI 清单支持顶层 `sheets:[{imagePath,background?}]`，每张只上传一次。`layers`（直接拆分）或 `repairs`（Mask 参考）中，新组件引用 `sheetIndex`（从 0 开始）和 `sheetRect:{x,y,w,h}`（生成图像素坐标，表示含留白的完整布局框）；已有组件继续用 `reuse`。服务端校验越界、重叠、混用字段及每张最多 8 个组件，再按原生像素切出独立 PNG。PNG 尺寸与画布布局保持分离，支持原有逐张回填。

### 拆分完成自动回填

组件入口的“拆分”提交 `autoContinue:true`：方案分析完成后，服务端继续建立图片任务；Mask 参考准备好后自动处理图层；有效结果直接进入 `ready`，由画布导入独立 PNG 并保存。流程在服务端衔接，关闭弹窗或刷新页面不会使任务停在方案完成。手动调整方案后点击“拆分”也使用此流程。

旧方案保留“查看 / 调整方案”，可用“继续拆分并回填”接上后续流程。`POST jobs/:planId/continue-split` 返回已有子任务或仅创建一次，并持久化 `continuationId`；重复请求、丢失响应和服务重启均优先找到已有 `planId` 对应任务，避免重复生图。失败或提交结果不确定时保留状态，不自动重复付费操作。单独使用旧 API 且未指定 `autoContinue` 的任务保留原有人工检查步骤。

自动回填仍执行层数、透明度、坐标、比例和来源版本校验。校验失败不导入；自动检查不代表生成图在视觉上完全等同原图，仍可通过“原图 / 拼回对照”查看。

### 候选验收与局部重做

画布发起的拆分携带 `reviewBeforePublish:true`：方案和 Mask 准备可以连续执行，切图和去背景后保留 `review_repairs`，同时自动把独立候选 PNG 显示到画布，组名标注“待检查”。用户逐层对照原图，保存重做标记和修改要求；只重做选中的 `regionId`，其他 PNG 保持原文件内容。确认候选版本后发布为 `ready`，沿用画布上的同一组图层，不再重复插入。关闭验收窗口或刷新不会丢失候选；执行任务不自动归档。

`canvasResult` 统一读取正式结果或 `repairPreview`，不修改后端验收状态。图层树、自动回填、任务卡片和回填诊断使用同一候选版本。局部重做更新已有图形的图片资源，保留形状 ID、位置、尺寸和父组；回填标记按任务和候选版本去重。诊断分别呈现候选/正式文件以及真实画布图层数量，不能把 `review_repairs` 误报为“尚未产生可回填图层”。

分辨率不足、透明背景或比例问题保留为图层警告；比例偏差通过透明留白保留原比例，不插值放大伪装高清。不可读文件、空图、错误图层清单仍属于技术失败；原提交保存在任务的 `candidate-submissions`，局部重做失败可恢复上一版候选。旧候选版本记录在 `candidateHistory`。

局部重做使用递增 `attempt`，Agent 的结果清单须回传同一批次；过期结果不能覆盖当前候选。每批只有一个独立执行任务回执，重复点击不能重复派发。新增接口：`review-candidates`、`retry-candidates`、`restore-candidates`；均携带候选 `revision`，以及 `regionIds` 和 `notes`。最终 `approve-repairs` 同时支持普通分层和 Mask 分层。旧任务保持其原有协议。
